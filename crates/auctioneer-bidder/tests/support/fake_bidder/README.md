# Shared Bidder Test Fixture

This is the single synthetic bidder for shared integration tests. Extend its
capabilities when the public bidder contract grows; do not import a production
bidder as an example or add a second test implementation.

Exchange and core reuse `auctioneer_bidder::test_support::fake_bidder` through the
bidder crate's `test-support` development feature. The canonical implementation
lives in `src/test_support/fake_bidder/`; schema and capture assets remain here.
Registry-only helpers belong to the bidder integration tests. No fake is added
to the serving registry, and the default library API is unchanged. Lower-layer
tests use synthetic data without depending upward on the executable fixture.

The implementation follows the same owner layout as the real bidders:

```text
src/test_support/fake_bidder/
  mod.rs       # public fixture API, counters, defaults and Bidder trait wiring
  controls.rs  # synthetic metadata, capability modes and observer types
  request.rs   # bounded construction, correlation and borrowed serialization
  response.rs  # sealed decoding, candidate classification and browser configs
```

Helper unit tests stay inline in their owning file. The existing public-contract
and allocation conformance targets remain under the crate's `tests/`, exercising
the exported fixture API rather than importing private implementation files.
The source-layout check covers this fixture explicitly, without adding a bidder
manifest, discovery entry or serving registration. Keep the root reexports stable
when extending capabilities. Its body-sensitive status rules and deliberate
coverage faults remain independent test controls, not production protocol policy.

| Boundary | Capability |
| --- | --- |
| Construction | Aggregate, split, bounded chunks, impression filtering, explicit no-request behavior, settings observation and immutable borrowed serialization |
| Host Services | Optional credential-reference preflight, coherent credential observation and borrowed floor-rate views; shared admission uses no real bidder |
| Endpoint | Declared values, reviewed host selection, encoding, preserved/appended/replaced queries and endpoint refusal |
| Metadata | Method, headers, reserved-header refusal, exact sent-impression coverage and explicit forged/empty coverage controls |
| Correlation | Call-local header, media and impression tokens |
| Diagnostics | Semantic refusal and nonfatal impression diagnostics |
| Finalization | Real gzip and exchange-owned header finalization |
| Response | Sealed node-budgeted decoding, status/no-bid handling, all four media, currencies and explicit cross-call candidates for exchange-filter fault tests |
| Partial Output | Valid bid siblings, candidate errors and browser-auction configurations |
| Debug | Supported OpenRTB projection and explicit unsupported-schema behavior |
| Registration | Observable constructor/execution context, synthetic declarations, aliases and feature ownership |
| Schemas | Independent synthetic compiler, format, numeric, cache and qualification controls |
| Resource Bounds | Counting-allocator controls varying payload, call count and caps independently |

The fake uses the real bounded sink, endpoint builder, metadata and sealed
response parser. It is never registered in a serving build and does not replace
an actual bidder's protocol or resource proof. Those conformance cases stay
beside their production owner and are automatically discovered into separate
conformance targets. Frozen external captures remain external evidence, not
expectations generated by this fake.

Synthetic source-table snippets are inert parser inputs for Rust import controls,
not foreign tooling or programs to execute.
