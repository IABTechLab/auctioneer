# M4 Auction Privacy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete M4 auction privacy without weakening M3 GDPR rules or waiting for unrelated provider certification.

**Architecture:** Parse and normalize privacy once, evaluate independent policies, and scrub each bidder-owned request after projection and before adapter construction. Reuse the existing config, privacy, exchange, and runtime crates. Pure parsing and transformation tasks can land independently; final activation must use the corrected M3b admission, bounded construction, and resource accounting paths.

**Tech Stack:** Rust 1.95.0, existing serde configuration/OpenRTB models, the bounded TCF parser, proptest, native and existing WASM builds. The selected internal GPP module and Unicode simple-fold dependency require the qualification described below; do not implement an unreviewed substitute codec or ASCII-only folding.

**Design:** [M4 design](../specs/2026-09-26-m4-privacy-design.md), including its eleven compatibility decisions, and the M4 portions of the [master spec](../specs/2026-05-21-auctioneer-openrtb-server-design.md).
