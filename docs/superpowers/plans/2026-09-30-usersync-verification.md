## Native Slow-Response Coverage

- Added `real_binary_recovers_all_aux_slots_after_slow_response_disconnects`
  to the production-binary transport suite. A control request must produce
  a successful body larger than 32 KiB. Sixteen connections each receive
  64 complete pipelined requests with a 1-KiB requested receive buffer;
  response heads are inspected without consuming the response bodies.
  The test checks 200/no-store/no-cookie headers, probe availability while
  reads are withheld, disconnect recovery, and successful admission of all
  16 aux slots in a subsequent held-body wave.
- The focused test passed 1/1. The initial experiment expected aux saturation
  while response reads were withheld and failed with healthy 200 responses.
  Inspection of pinned EdgeZero's `AxumEgressBody` confirms application
  completion at `HostHandoff`, after the source is consumed by Hyper. TCP
  delivery acknowledgment is outside that contract. The test therefore
  checks the supported cleanup and availability behavior; it does not
  establish a physical-wire completion/deadline guarantee.
- The request uses `serde_json::json!` and structured serialization.
  `serde_json` is an adapter test dependency; no package version changed.
  The final expanded transport suite passed 12/12 in both default and
  `insecure-bidders` modes, including the additional URL-bearing log sentinel.
- The first expanded full-suite run passed 10/11 and exposed a harness
  timeout bug: a sub-microsecond remaining socket timeout is not representable
  on macOS. The helper now clamps each blocking read to at least 1 ms, retains
  its overall deadline, and stops on a complete Content-Length-framed response
  rather than requiring peer close. An inline completion-boundary regression
  covers every truncated prefix, complete bodies and bodyless responses.
