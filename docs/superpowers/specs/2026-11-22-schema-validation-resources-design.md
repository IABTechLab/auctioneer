## 2. Scope And Non-Goals

Include the current per-call path: bounded borrowed-input measurement, admission/dispatch coordination, declaration-specific cache construction, generated validation and reachable runtime primitives, regex searches, hostname/UUID callbacks, failure cleanup and cache destruction. Include the sum of work across attempts and admitted evaluations, and simultaneous storage/call nesting, not just the largest observed successful call.

Within this proof-only package, preserve current serving behavior: the engine and compiler patches, schemas and formats, workload/input limits, work-token policy, reservations, original deadlines, impression-local errors and guest-publication restrictions. This does not authorize retaining a superseded path when its replacement is adopted: the hard-cut contract below requires deletion at that cutover. This package does not install a descriptor or activate a previously unqualified path. Do not implement runtime metering, cache reuse/pooling (#229), a replacement validator, a new crate, a new test binary or a second registry/configuration mechanism.

Measurements corroborate independently derived bounds; they cannot select a bound, coefficient or threshold. A missing proof, unsupported operation or incompatible source tuple refuses certification. No partial owner set, hypothetical target fact, disabled bidder or unimplemented placeholder can become a zero-cost qualification.

## 5. Input And Invocation Premises

The common model takes independently supplied, checked dimensions:

- Compact serialized parameter bytes `B`, value-plus-object-key nodes `J` and container depth `D`, matching `SchemaInputStats`, including scalar and empty-container cases.
- Actual generated branch/helper structure, schema nesting and container traversals, including branch alternatives that revisit the same value.
- A derived finite number of searches per program and callback invocations per evaluation, not a count inferred from an observed workload or assumed equal to `J`.
- Caller evaluation-attempt and admitted-evaluation populations, with their actual ordering and maximum simultaneous active lifetimes.

Read the current limits from their owning code. At the basis checkpoint native input admission is 65,536 compact bytes, 4,096 nodes and depth 32; hostname rejects lengths above 255. These are existing premises, not new tunable controls or permission to clamp supported input.

Prove the relationship between admitted JSON size, decoded string/key bytes and every regex/runtime-helper haystack. Include escaped/non-ASCII strings and keys. Derive helper-call multiplicity from actual expanded control flow and bounded instance shape. Freeze the accepted operation grammar and work-unit definitions before measurements. An unknown helper, cycle, recursion edge or unbounded traversal refuses rather than inheriting an unrelated parser-depth assumption.

Preflight occurs before `SchemaWorkBudget::evaluate`. Bound its attempted traversals and refused-prefix cleanup even when no validator is admitted or aggregate work is already exhausted. Do not bound attempts by successful calls or pretend a later work debit precharged an earlier walk. Caller populations must be reconciled with existing impression/bidder limits, not independently widened or omitted.

The injected expiry callback is an explicit external-service boundary, not a free coordinator instruction. The source join covers only the recorded caller binding, never every possible `F: FnMut() -> bool`. Derive callback invocation and overlap bounds from the actual entry, budget-check and exit sites: the current ordinary return path has at most three calls, while entry expiry/unavailability/input refusal and admission refusal have their own shorter prefixes. Prove those prefixes, including panic/error alternatives, and bind the caller's `dyn Clock` / `RequestClock` / SDK-injected `MonotonicClock` chain. The common descriptor names that boundary and carries required work, requested-storage, retained-state and stack facts with the exact callback/source/features identity. #72-#75's actual host/embedding binding owners must discharge those external facts; an arbitrary new callback is not automatically covered. Missing or mismatched facts refuse that binding's evaluation/admission and target acceptance, never becoming zero or being replaced by the allocator fixture's `|| false`. This parameterization does not excuse an unclassified common source edge: #47 must identify the boundary completely and prove all caller-side multiplicities/lifetimes before common source completion. No new production API or cost is installed.

## 6. Validation Storage And Lifetime

**Approved host-entropy amendment, 2026-11-24:** Under the current `std` feature, fresh lazy-DFA state maps use `std::collections::HashMap`. `RandomState::new` can initialize thread-local hash seeds through the platform entropy implementation; the pinned Linux implementation contains an uncapped `EINTR` retry. Successful process-wide schema initialization does not prove that every validating thread is warm. Model this as an explicitly identified host service, not constant/free local work or an assumed warm-thread guarantee. Bind the exact cache-construction, standard-library, platform, feature and service identities. Derive `N_seed` from all reachable state-map/seed construction sites, including sibling caches, hostname callbacks and partial-construction prefixes. Conservatively permit each source-bound construction to be cold; do not require or add a thread cache, runtime warming or a new serving hook. A source-proven non-`std` map implementation may exclude this service only for that exact feature/source tuple.

For each work component, the required entropy-body fact is `E_i`; its work term is `N_seed*E_i`, separate from local source work and clock bodies. Require matched transient-storage, retained-thread-state, stack and failure/cleanup facts as well. Transient entropy work occurs during cache construction and can overlap already-live sibling/wrapper owners. Retained state follows its actual thread/host lifetime, not one new resident charge per cache or invocation; adapter owners must bind its thread multiplicity and map it to an existing memory domain once. Unknown host facts refuse binding evaluation and target acceptance, while the common proof must still establish every local edge, call count and overlap. Missing common seed-site or lifetime derivations remain #47 work. This amendment changes neither runtime token coefficients/debits nor the additive memory equation, limits, reservations, engine, standard-library implementation or production behavior.

The exact service entry is `std::hash::RandomState::new`. Supplied facts cover its whole warm/cold body, including thread-local state handling and any platform seed acquisition. Local map/cache constructor prefixes, ownership, hashing, probing, growth and destruction remain common obligations; this boundary cannot exempt an unrelated library helper. A private lower-level seed function is not an interchangeable service identity. The model conservatively counts each reachable `RandomState::new` call, without relying on how often a thread actually reaches the cold branch.

Model the production lifetime: a fresh declaration-specific cache is constructed inside the admitted closure, used by the generated validator, then dropped before returning. Include partial cache construction, growth/relocation, failure cleanup and final destruction. Repeated-cache observations may corroborate a component but cannot replace this fresh-per-evaluation path.

Each cache child retains its existing disjoint sub-owner attribution. Immutable regex programs, static cells and boot-time initialization stay in C/I. Mutable search storage and per-call cache construction belong to V. A fallback term already included in a broader component bound receives an explicit covered-by relation, not another summand and not an unproved zero. Excluding actual search fallback needs the complete source-bound strategy/capacity/quit proof; inactive eager cache allocation may still be live.

For one evaluation, define the requested-storage envelope as the checked maximum over source-derived lifetime states of the sum of disjoint live owners plus justified transient overlap. Include sibling caches and the enclosing generated cache while a hostname callback constructs, searches with and drops its fresh local cache. A shared callback definition is one source owner but can be invoked many times; serial callbacks permit a peak maximum only after proving non-overlap. Sum their work, not their peak storage. UUID's fixed decode buffer belongs to the call-frame model; its uppercase scan is input-dependent work.

At auction composition, storage follows the existing serial validation lifetime and its funded per-auction owner, not the number of completed calls. Work follows all applicable attempts/admitted calls and is cumulative. Any source change introducing overlapping validation or escaping/reset/cloned/rebound caches invalidates the serial/fixed-cache premise and refuses until separately reviewed. Preserve checked arithmetic and independent populations.

## 7. Evaluation Work

Define a checked source-level work ledger with explicit units and coverage, rather than one unnamed number. Cover input/serialization-sizing visits, generated branches and property/array scans, comparisons, string/Unicode operations, equality/uniqueness and reachable runtime helpers, callback work, cache construction/growth/cleanup and selected search transitions/state processing. Establish the actual primitive closure from the emitted validator and pinned dependency sources; the examples are not a whitelist that silently ignores other operations.

Use source-proven upper bounds for the worst admitted valid or invalid path, including early return, late failure, supported fallback/quit behavior and cleanup. Mutually exclusive branches may use a maximum only with a branch-exclusivity proof; loops and repeated callbacks use derived invocation counts. If a runtime primitive allocates or recurses, carry that storage/stack obligation to the corresponding lifetime model instead of considering its work count sufficient.

Byte-progress arithmetic and NFA/epsilon heap-stack dimensions remain distinct from evaluation-work units. Qualification-tool graph-exploration budgets are not serving work limits. Do not equate source record/byte visits, abstract validation operations, machine instructions, elapsed milliseconds or the native token formula. Schema/compiler maintainers own the source-work grammar, counted primitive actions and derivations under #47; freeze that semantic contract before Task 4's derivations and freeze its resulting coefficients before using new observations to corroborate them. Existing baseline observations remain historical/regression controls, not a source of chosen coefficients.

The approved correspondence is componentwise shape, not token-to-CPU conversion. Let `T(B,J) = 1024 + 16*B + 128*J` be the actual existing debit for an admitted evaluation. For each work component `i` of declaration `k`, prove `V_i,k(B,J) <= a_i,k + b_i,k*B + c_i,k*J` for the admitted closure: fresh cache construction, validation, format callbacks and release. Coefficients are source-derived counts in that component's own units. Any use of schema branches, depth, haystack or node maxima to obtain them must identify the existing fixed cap and the checked derivation; it may not shrink the workload. Require explicit source witnesses for zero coefficients, never missing-value defaults. No affine certificate is granted when that derivation is missing.

Derive, rather than choose, `Q_i,k = max(ceil(a_i,k/1024), ceil(b_i,k/16), ceil(c_i,k/128))`, with checked arithmetic and dimensions. This proves `V_i,k <= Q_i,k*T`; a source-bound maximum over declarations supplies `Q_i` for auction composition. The ratios report how many source-count units each admitted token debit can upper-bound; they are not weights assigning an intrinsic meaning to one token, need not equal one, and establish neither CPU nor latency adequacy. Prove correspondence to the checked production policy tuple; do not adjust coefficients, units or limits to improve these ratios.

Keep uncharged work outside that inequality. Prove a separate `P_i(A; existing caps)` for input measurement, local admission/coordination and rejected/failure-prefix cleanup outside the admitted closure, using all attempted evaluations `A`, not only successes or debited calls. Parameterize identified external expiry-callback bodies as `N_clock*H_i` and host entropy bodies as `N_seed*E_i`, with independently source-proven invocation/lifetime bounds and required matched host facts. Use disjoint stages so service setup/body, input walks and local admitted work are each counted once. The whole-auction bound is `P_i + sum(V_i,k) + N_clock*H_i + N_seed*E_i <= P_i + Q_i*sum(T) + N_clock*H_i + N_seed*E_i`. The local `V_i,k` excludes those identified external bodies, not their caller-side setup, cleanup or multiplicity obligations. An auction's admitted debit limit bounds only `sum(T)`; it does not fund, debit or eliminate `P_i` or either external-service term. Preserve the actual zero debit for refused preflight and report its funding as `not_established` here. Do not assign it to the request-parse budget without an independent ownership/funding proof.

#47 may complete only with all common derivations, the checked componentwise correspondence, complete attempted-work bounds, identified external-service premises and storage/structural-stack obligations delivered. Unknown common coefficients, attempts, ownership, or unsupported source paths remain incomplete. Numerical policy adequacy remains `not_evaluated`, never automatically `PolicyIncompatible` just because tokens lack a physical unit. Under #72-#75, adapter and schema/compiler maintainers must obtain a separately reviewed numerical cost/policy interpretation, actual target facts and explicit acceptance/funding for the complete bound, including uncharged attempts and host callbacks, before claiming target qualification. Missing or failing acceptance blocks #88-#90 qualified activation; a valid shape proof cannot waive it. Runtime token coefficients, single/auction limits, scratch reservations, engine and compiler stay unchanged; any later policy or limit change needs separate approval.

A source-level work bound is not a latency or CPU-instruction certificate. The current validator is synchronous; deadline checks before/after a call do not provide interruption inside a regex search. Preserve those checks and state the distinction, without inventing cooperative cancellation hooks.

## 8. Structural Stack And Target Inputs

Derive logical call nesting from the actual generated declarations, input traversal, callback/coordinator paths and pinned runtime-helper control flow. Distinguish schema nesting from instance container depth, repeated branch work from simultaneous call depth, and explicit regex heap-stack records from the machine stack.

Express a checked peak call-path composition in terms of required target frame/scratch facts. Add frames that can coexist on one path; take a maximum across alternatives only when their exclusivity is proven. Include called serializer/library routines, fixed UUID storage, cache construction/search/drop and declared panic/error-path alternatives. An unclassified recursive cycle, call/frame owner or nesting contribution refuses common source completion; do not guess a multiplier from input depth. A declared but unavailable target frame-byte fact instead refuses numeric/target evaluation, never becoming zero; target consumers must also match the artifact's actual panic/error-path mode.

Common #47 evidence supplies the structural bounds, source/helper identities, frame-owner requirements and composition rule. #72-#75 must supply matched actual artifact/compiler/ABI/profile/feature frame sizes, machine-stack and allocator facts and prove correspondence. Host `size_of`, a local stack sample, source AST size, a WASM section size or a logical heap-stack count does not supply these facts. No new layout API or vendor patch is preapproved here.

**Approved allocation-success premise, 2026-11-24:** The validation work/storage/stack theorem is conditional on its allocation requests succeeding. It still covers supported normal returns, returned errors, partial construction and ordinary unwind/cleanup paths under that premise. Terminal allocation-failure handling and its fatal diagnostics are outside this bound: the pinned std handler can reach an interrupted stderr-write retry without a finite local retry bound. This is an explicit theorem-scope exclusion, not a zero-cost leaf, a new external service, a bounded-abort claim, or permission to discard ordinary error/unwind cleanup. Ordinary `panic = "abort"` does not prove immediate bounded termination.

Keep allocation success as a separately named, source/allocator/artifact-bound target premise. Requested bytes, measured peaks, headroom and a hypothetical supplied value do not establish it. Missing or incompatible support refuses actual binding/target evaluation and activation. The common report must expose the premise and fatal-handler exclusion; #72-#75 must discharge the actual premise before using the conditional result. #47 still owes all common returning/error/unwind derivations and exact allocation sites. No allocator, error hook, production behavior, resource limit, reservation or accounting equation changes under this amendment.

Keep heap/requested scratch, inline cache storage and machine stack distinct until the adapter owner maps them to its existing memory domains exactly once. In particular, Fastly's separate published stack allowance must not be folded into primary memory or treated as proof that the application fits.
